## 1. 这套东西到底在干什么

一句话：**狗一边走一边用雷达看清周围，你的电脑同步把它看到的东西拼成一张三维地图。**

分工是这样的：

```
   机器狗背上                        你的电脑
┌──────────────────┐            ┌──────────────────┐
│ 雷达 Mid360      │            │                  │
│   ↓ 每秒 10 圈   │   网线     │  把每一帧攒起来  │
│ 小电脑 Orin      │ ────────→  │  变成一张地图    │
│  负责"算"        │  千兆交换机 │  负责"看"        │
└──────────────────┘            └──────────────────┘
```

- **狗端**（Orin Nano）跑算法，把雷达原始点算成"这一帧我在哪、周围长什么样"。
- **电脑端**只做两件事：接收、显示。
- 中间必须有一根**网线**（不是 WiFi）。WiFi 带宽不够，画面会一顿一顿。

所以整个流程永远是：**先让狗跑起来 → 再让电脑看**。顺序反了电脑就没东西看。

## 2. 开工前，桌上应该有这些

| 东西 | 说明 |
|---|---|
| 机器狗 Go2 | 电池有电（开机后狗会站起来，别让它摔了） |
| 雷达 Mid360 | 装在狗头/背上，宇树套装是一根 M8 复合线，插上就有电 |
| 千兆交换机 | 五口的小交换机就行，要通电 |
| 网线 × 3 | 电脑—交换机、狗—交换机、雷达—交换机 |
| 你的电脑 | Ubuntu 22.04，`~/FLMap.2` 这个仓库已经装好（没装见 §9） |

> 三根线**不分顺序**，交换机上随便哪个口都行，也不需要"交叉线"。
> 全世界的地址都是固定好的，你不用配路由、不用改 IP。

## 3. 接线和开机（唯一容易搞错的地方）

### 3.1 插线

```
              ┌──────── 千兆交换机 ────────┐
              │        │          │       │
          [网线1]   [网线2]    [网线3]
              │        │          │
         电脑网口   狗的网口    雷达网口
      192.168.123.10   .18        .221
```

三个地址记不住没关系，只要记住**"电脑、狗、雷达，各一根线进交换机"**。

### 3.2 开机，按这个顺序

1. **交换机先通电。**
2. **插好三根线。**
3. **再给狗开机**（电池开关）。
4. **等 40–60 秒。** 狗要先站起来、内部小电脑要启动，急不得。

> 雷达不用单独开。宇树套装里雷达的电是跟着狗一起供的，狗醒了雷达就醒。
> 如果你是零售版雷达、电源是单独的 XT30 头，**记得先把 12V 接上**。

### 3.3 验证：电脑能不能看到它们

打开电脑的终端，敲：

```bash
ping -c3 192.168.123.18     # 狗
ping -c3 192.168.123.221    # 雷达
```

✅ **看到 `0% packet loss` 就对了**（三个包全回来）。

如果狗能 ping 通、雷达不通：多半是雷达没供电，或者 M8 线没插到底。

## 4. 三个窗口，各干一件事

整个系统就靠三个终端窗口。**建议按 A → B → C 的顺序开**，每个窗口一直开着别关。

打个比方：A 是"对表的人"，B 是"开狗的人"，C 是"看屏幕的人"。

### 窗口 A（电脑）：给狗对表

**为什么要有这一步**：狗身上的小电脑没有电池时钟，一断电时间就乱了（可能回到 2023 年）。
时间不对，地图和画面就会对不上，RViz 会疯狂刷红字。所以要电脑当"标准钟"，让狗定时来对。

```bash
cd ~/FLMap.2
./scripts/clock_sync.sh start
```

✅ 看到任意一行带 `[ ok ]` 就成功了，比如：

```
[ ok ] 授时服务已启动: http://192.168.123.10:8000/time
```

> 这个窗口**开着就别关**，它只是在后台当钟表。关掉不影响已经建好的图，
> 但狗会慢慢走偏时间。

### 窗口 B（连到狗）：启动建图

新开一个终端：

```bash
ssh unitree@192.168.123.18
```

第一次连会问 `yes/no`，输 `yes`；要密码就输 `123`（宇树默认）。

登录后屏幕上会冒出一句：

```
ros:foxy(1) noetic(2) ?
```

👉 **输入 `1` 回车。** 这是在问你用哪个版本的 ROS，狗上装的是 Foxy（第 1 个）。

> 你也可以直接回车跳过，脚本自己会选对。选 1 唯一的小副作用是它顺手设了一个
> 坏掉的网络配置，但我们的启动脚本会自动忽略掉，不用管。

然后：

```bash
cd ~/flmap3_ws
./scripts/edge_control.sh
```

它会自己按顺序拉起三个程序（雷达驱动 → 建图算法 → 发给电脑的桥），大约 11 秒，
最后出现一个提示符：

```
flmap>
```

✅ **看到 `flmap>` 就说明狗端活了。** 这时候再看一眼有没有这行：

```
[ ok ]  /cloud_registered: average rate: 10.0
```

有就是完美。如果写的是"统计还没出"，别慌，等 10 秒敲一下 `status` 再看。

### 窗口 C（电脑）：看画面

再新开一个终端（**不要关 A**）：

```bash
cd ~/FLMap.2
./scripts/pc_view.sh
```

它会先自检一遍网络，然后弹出一个 RViz 窗口。✅ 看到类似这行就通了：

```
[ ok ] 收到点云，当前帧 8812 点，约 9.9 Hz
```

RViz 里应该出现四样东西：

| 画面里的东西 | 是什么 |
|---|---|
| 一大片灰白色的点 | 已经扫出来的地图，会越来越大 |
| 一束会闪的点 | 雷达"这一瞬间"看到的东西 |
| 一个箭头 | 狗现在的位置和朝向 |
| 一条线 | 狗走过的路线 |

**到这一步，你就可以推着狗（或让它走）开始扫了。**

### 提醒：你脚下现在有三层，别搞混

狗是没有屏幕和键盘的，所有操作都是**在你自己电脑的终端里**敲，只是敲完
`ssh` 之后，命令实际在狗身上执行。所以同一个窗口，提示符会变两次：

```
你电脑的终端            cj@yourpc:~$          ← 第 1 层：你自己的电脑
      │  ssh unitree@192.168.123.18
      ▼
狗的系统                unitree@ubuntu:~$     ← 第 2 层：狗的 Linux
      │  ./scripts/edge_control.sh
      ▼
建图控制台              flmap>                ← 第 3 层：建图程序内部
```

记住三条就够：

1. **提示符以 `$` 结尾** → 这是普通命令行，`cd`、`ls`、`sudo poweroff` 都在这里敲。
2. **提示符是 `flmap>`** → 这已经是建图程序内部了，**不是** shell。只能敲
   `start` / `stop` / `status` / `quit` 这几个词。在这里敲 `ros2 ...` 或 `ls`
   只会回一句 `未知命令: ls`，那不是坏了，是不认这个命令。敲 `help` 可以看全部命令。
3. **想往回退**：`flmap>` 里敲 `quit` 回到狗的 Linux；再敲 `exit` 断开 ssh 回到自己电脑。

> ⚠️ 在 `flmap>` 里按 **Ctrl-C 不是"取消当前输入"**，而是直接退出整个控制台
> （脚本会先自动 `stop` 存档，再关掉三个节点）。想退出就用 `quit`，别按 Ctrl-C。

> 需要同时看日志时，**再开一个终端重新 `ssh` 一次**就行，两个会话互不干扰
> （第二个窗口进去后不用跑 `edge_control.sh`，直接 `tail -f /tmp/flmap_edge/mapping.log`）。

## 5. 开始扫、暂停、结束

所有操作都在**窗口 B**的 `flmap>` 提示符后面敲。

```
flmap> start
```

`start` 的意思是"从现在开始录，并给我建一个文件夹存起来"。
注意：**驱动和算法在你进控制台的时候就已经在跑了**，`start` 只是开始录。

| 你想干的事 | 敲 | 说明 |
|---|---|---|
| 开始一次新扫描 | `start` | 建文件夹 + 开始录包 |
| 中途歇一下（不想录这段） | `pause` | 地图还在长，只是不录 |
| 继续录 | `resume` | |
| 结束这次扫描 | `stop` | 停止录包，并自动导出一份 `map.pcd` |
| 看现在状态 | `status` | 进程、频率、温度、内存 |
| 看传输压缩比 | `stats` | 发出去的点被压掉了多少 |
| 检查网线好不好 | `link` | 网口速率、到电脑和雷达的延迟 |
| 全部关掉走人 | `quit` | 会自动先 `stop` |

> `status` 里频率显示 **9 左右是正常的**，不是坏了。刚启动那十几秒会把慢的也算进平均，
> 稳定后就跳到 10.0。

## 6. 东西都存在哪

每次 `start` 都会在**狗**上建一个按时间命名的文件夹：

```
~/bags/2026-10-19_13-52-32/
├── scan/            ← 原始录像（最重要，有它就能重新导出地图）
├── map.pcd          ← 导出的三维地图，可以用 CloudCompare 打开
├── info.txt         ← 这次扫描的开始时间、话题清单
├── record.log       ← 录制的日志
└── pcd_export.log   ← 导出地图的日志（导出失败先看这个）
```

想拷回电脑（千兆网，几十 MB 一两秒）。**注意：下面的 `~/bags/...` 是狗上的路径，
在你自己的电脑上是没有的** —— 你在 ssh 里 `ls` 能看到，退出 ssh 就看不到了，
这是最常见的一次困惑：

```bash
# 在你的电脑上执行：单个文件
scp unitree@192.168.123.18:~/bags/2026-10-19_13-52-32/map.pcd ~/Desktop/
# 整个文件夹（含录像母带）
scp -r unitree@192.168.123.18:~/bags/2026-10-19_13-52-32 ~/Desktop/
```

> **记住一件事**：`scan/` 里的录像才是"母带"，`map.pcd` 是从它转出来的。
> 所以哪怕 `map.pcd` 没生成、或者转坏了，**只要 `scan/` 还在，就不用重扫**，
> 重新转一次就行（见 §7 最后一条）。

## 7. 收工：关机的正确顺序

**先让狗停 → 再关电脑 → 最后断电。** 顺序错了会写坏文件。

```bash
# ① 窗口 B（狗端控制台里）
flmap> stop          # 存地图
flmap> quit          # 关程序

# ② 窗口 C：按 Ctrl-C 退出看图
# ③ 窗口 A：停掉对表服务
cd ~/FLMap.2 && ./scripts/clock_sync.sh stop

# ④ 狗端（还在 ssh 里）
sudo poweroff        # 密码 123；等风扇停、灯灭，约 20 秒

# ⑤ 最后关电池开关 / 拔电源
```

> **为什么不能直接拔电池**：关机那一刻正在往磁盘写地图和日志，硬断会留下半截文件，
> 而且**不会报错**——你下次打开才发现少了一半。

下次开机，回到 §3 重新来一遍即可。**换新场景不需要删任何文件**：
地图存在内存里，程序一重起就清空了，旧文件留着当历史。

> **如果 `stop` 提示"PCD 导出失败"**：先别重扫。录像还在，直接重新转：
>
> ```bash
> cd ~/flmap3_ws
> /usr/bin/python3 scripts/bag_to_pcd.py ~/bags/<那个文件夹>/scan ~/bags/<那个文件夹>/map.pcd
> ```

> 关机每一步为什么这么排、拔错顺序会坏什么、断电后怎么救 → 见
> [13-shutdown.md](13-shutdown.md)（关机与断连教程）。

## 8. 出问题了，先看这张表

| 你看到的 | 八成是 | 怎么办 |
|---|---|---|
| `ping 192.168.123.18` 不通 | 三件事：网线/狗没开机/电脑的 IP 掉了 | 先看交换机灯闪不闪；灯闪就敲 `./scripts/pc_net_fix.sh` |
| 狗通了，雷达 `.221` 不通 | 雷达没供电（M8 线松了） | 把狗头上那根线按到底；零售版先接 12V |
| 窗口 B 里节点一闪就退 | 登录时那个 1/2 选错了别的项，或网络配置被污染 | 退出重登，老老实实输 `1`；还不行就 `quit` 重进 |
| 窗口 C 说"没收到点云" | 狗端还没出图 | 回窗口 B 敲 `status`，看 `/cloud_registered` 有没有频率 |
| RViz 一片空白，但有数据 | 电脑上有第二个网卡抢了流量 | `ip route get 192.168.123.18`，看是不是走了 WiFi |
| 画面里点挤成一小团 / 飞到天上 | 点云数据格式坏了（少见） | 跑 `./tools/diag/run_bridge_selftest.sh -n 5000`，期望 `5000/5000` |
| RViz 报 `GLXContext` 打不开 | 电脑显卡驱动 / 远程桌面没有图形加速 | 用 `./scripts/pc_view.sh --headless` 只收数据，或本机直接开 |
| 想不起来哪一步没做 | —— | 跑 `cd ~/FLMap.2 && ./scripts/link_probe.sh`，它会逐层告诉你断在哪 |

一条命令做全面体检（连不上、看不明白时先跑这个）：

```bash
cd ~/FLMap.2 && ./scripts/link_probe.sh
```

它按"网线 → 延迟 → SSH → 数据发现 → 点云 → 带宽"六层往下查，红在哪一层就是哪一层的问题。

> 更多症状和原理解释：[06-troubleshooting.md](06-troubleshooting.md)。
> 点云形状不对这种疑难杂症：[10-pitfalls.md](10-pitfalls.md)。

## 9. 只在新电脑上做一次的事

换电脑、重装系统、或者第一次在这台机器上跑，才需要做这些。做过一次就永远不用再管。

```bash
cd ~/FLMap.2
./setup.sh                      # 编译，约 5 分钟，末尾要看到 "编译完成"

# 给电脑网口配固定地址（只做一次）
sudo nmcli connection add type ethernet ifname enp131s0 con-name go2-wired \
    ipv4.method manual ipv4.addresses 192.168.123.10/24 ipv4.gateway "" ipv4.dns ""
sudo nmcli connection up go2-wired

# 让狗端也能自动对表（只做一次，需要狗端密码）
./scripts/clock_sync.sh start
./scripts/clock_sync.sh install

# 把代码推到狗上并编译（约 5 分钟）
./scripts/deploy_edge.sh
```

> ⚠️ **配网口时千万不要填网关（gateway）**。填了之后你电脑的全部上网流量都会
> 往狗身上撞，表现就是"能 ping 通狗，但浏览器打不开网页"。

> 换了狗端代码才需要重新 `deploy_edge.sh`。只改配置参数不用编译，见
> [11-runbook §7](11-runbook.md)。

## 10. 名词小抄

看到文档里这些词，不用怕，都是很朴素的东西：

| 词 | 人话 |
|---|---|
| 点云 | 雷达一圈扫出来的一堆点，每个点有 x/y/z 坐标，连起来就是物体的形状 |
| 话题（topic） | 程序之间传数据的"频道名"，比如 `/cloud_registered` 就是"算好的这一帧点云" |
| ROS | 机器人领域的一套通信框架，狗和电脑靠它互相找到对方 |
| DDS | ROS 底层真正干活的通信库，两端版本/配置要一致才能互相看见 |
| 域（domain） | DDS 的"房间号"。房间号不同就互相看不见。我们用 42，避开狗自带的 0 |
| LIO | 雷达惯性里程计：只用雷达+陀螺仪就能算出"我在哪"，不需要 GPS |
| FAST-LIO2 | 我们用的那个 LIO 算法，狗端跑的就是它 |
| 体素降采样 | 把空间切成小格子，每格只留一个点。格子越大，数据越少、越糊 |
| PCD | 一种存三维点云的文件格式，可以用 CloudCompare / MeshLab 打开 |
| rosbag | 把一段时间内所有话题的数据原样录下来的"录像文件" |
| RViz | 电脑上那个三维查看器，专门用来看 ROS 的数据 |
| 授时 / 对表 | 让狗的时间和电脑一致。不一致会导致画面抖动、地图错位 |
| TF | 坐标变换。RViz 靠它把雷达看到的点摆到正确位置 |
