# 20 · 静置建图"某帧倾斜"的定位（IMU 尖峰 + 视场剧变）

> 现象：地图里偶尔出现一帧/一小段点云整体歪掉，之后又"自己回来了"，
> 同一面墙在地图上有 3–4 层嵌套轮廓。
>
> **前提修正（2026-10-21 下午）**：雷达**没有装在狗身上**，是平放在桌面上采集的。
> 因此此前"Go2 步态落地冲击把姿态甩出去"的结论作废——静置设备不会产生 4.7 g。
> 本文按"设备静置"重新定因。
>
> 结论：**Mid360 内置 IMU 会偶发输出不可能存在的角速度尖峰（10–20 rad/s、4–6 g、
> 5 ms 内符号翻转）；原代码不做任何校验，尖峰被直接积进姿态，单帧即可把预测甩出
> 20°。** 现已加入 `imu-guard` 防护。

### 2.5 因果链

```
真实扰动（11 cm / 16° yaw，6 秒）
        │
        ├──→ 视场剧变：点数 −43%、大量近处遮挡 → 激光匹配可用的约束骤减
        │
        └──→ IMU 同时输出 19.7 rad/s / 6.3 g 的假尖峰（物理不可能）
                    │
                    ▼
        IMU_Processing.cpp 无任何校验，Exp(angvel,dt) 直接积分
                    │
                    ▼
        预测姿态被甩出 roll 20.8° / pitch 27.9°
                    │
                    ▼
        激光匹配从错误初值收敛 → 位姿停在 (0.11, -0.03, 16.3°) 并锁死
                    │
                    ▼
        这 6 秒的点云以错误姿态拼进地图 → 同一面墙 3–4 层重影
```

重影的**残余是不可逆的**：19 s 之后位姿很稳，但已经拼错的点云留在 map 里了。

## 4. 修复：`imu-guard`（已实施）

位置：`src/FAST_LIO2_ROS2/src/IMU_Processing.cpp`，`UndistortPcl` 的积分循环。

### 4.1 判据（三重，缺一不可）

| 判据 | 阈值 | 依据 |
|---|---|---|
| 幅值 `|angvel|` | **3 rad/s**（172 °/s） | 狗走 0.3–1 m/s 的转向 < 1 rad/s；实测异常簇峰值 1.0–19.7 rad/s |
| 幅值 `|acc|` | **3.5 g** | 静置基线 0.99 g；温和扰动 < 2 g；实测异常段 4.7–6.3 g |
| 变化率 `|Δangvel|/dt` | **500 rad/s²** | 真实刚体（含人手快甩）上限约 500；实测尖峰 5 ms 内跳变等效 **5700** |
| 自适应 `|angvel|` | **max(1.0, 6×运动基线)** | 静置基线 0.021 → 门槛 1.0；行走基线 0.3 → 门槛 1.8，不误伤正常转身 |
| 连续超阈值时长 | **0.6 s** | 超过则判为真实剧烈运动，放行限幅值 |

只用幅值一条不够：本次数据里有一半异常帧幅值只有 1–2 rad/s（57–115 °/s），
单靠 3 rad/s 会漏；但它们全都是 5 ms 内的跳变，靠变化率判据能全部抓到。

**自适应基线必须只在"判为正常"的采样上更新**，否则几帧 19 rad/s 就能把基线
顶到 0.8，门槛自动升到 4.8，后面的异常就全漏了（第一版实现就踩了这个坑）。

### 4.2 动作

1. **限幅**：超阈时把 `angvel_avr` / `acc_avr` 按比例压到阈值（保留方向）。
   后面逐点去畸变读的是 `IMUpose[i].gyr`，即限幅后的值，整帧不会被扭。
2. **暂停积分**：`dt = 0`，`R_imu / pos_imu / vel_imu` 全部保持 —— 等于"这段 IMU 不采信"。
3. **膨胀协方差**：旋转 +0.01、位置 +1 m²、速度 +4 (m/s)²，让随后的激光更新主导修正。
4. **日志**：每 20 帧打印一次 `[IMU][guard] spike |g|=... |a|=... -> hold`。

### 4.3 离线标定（`scripts/sim_imu_guard.py`）

用与 C++ 完全相同的规则重放 bag 里的 IMU，扣掉静态 bias 后只统计"虚假转角"：

| bag | 不设防虚假转角 | 设防后 | 被拦采样 | 峰值 \|gyro\| |
|---|---|---|---|---|
| **11-54-52**（异常） | 278.8° | 162.6° | 59 帧 | 19.70 rad/s |
| 12-20-17（干净） | 2.4° | 2.4° | **0 帧** | 0.04 rad/s |
| 12-01-54（干净） | 1.4° | 1.4° | **0 帧** | 0.04 rad/s |
| 12-04-52（干净） | 2.0° | 2.0° | **0 帧** | 0.04 rad/s |

两个结论：

- **干净数据零误伤**——三段静置 bag 一帧都不拦，说明阈值不会影响正常建图。
- **致命尖峰被全拦**：所有 > 3 rad/s 的采样（含 19.7 rad/s 那颗）都被拦下；
  剩下的 162° 来自 0.5–1.0 rad/s 的中等漂移，这类偏差激光匹配能自行拉回，
  不会造成 20° 的姿态甩动。

参数可用 `--gyro` / `--acc` / `--jerk` / `--hold` 现场重标定。

## 5. 仍未闭环的部分

### 5.1 IMU 为什么坏

这次是"雷达被碰/被遮挡"的 3.5 秒里坏。有两种可能，尚未区分：

- **移动/遮挡导致 Livox 内部 IMU 读数异常**（固件或 SPI 传输层面的问题）
- **碰巧同时发生的独立故障**（时间上重合纯属偶然）

验证方法：雷达**完全不动**，分别做 a) 用手掌在雷达前方扫动 3 秒；b) 把雷达水平
转 30° 再转回。各做 3 次，看 `diag_imu_raw.py` 是否每次都报 `|g| > 8`。
如果"只遮挡不动"也触发，说明是视场/固件层面的问题，而不是机械振动。

### 5.2 用户说的"每隔若干秒"

本段 bag 的异常只出现**一次**（14.98–18.45 s），不是周期性。如果实际观察到的是
"每隔十几秒反复出现"，那有两种情况：

- 每次都被碰到/遮挡（物理上说得通：伸手调设备、线缆被拉）
- 或者看到的是另一个现象（例如 RViz 里累加器刷新时的显示间歇），需要新录一段
  **全程无人接触**的 bag 来判断

判据：`python3 scripts/diag_imu_raw.py <bag>` 的 `[4]` 表里，如果簇起始时刻均匀
分布在整个时间轴上，就是周期性；像本例这样挤在一段里，就是单次事件。
