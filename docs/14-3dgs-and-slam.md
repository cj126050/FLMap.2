# 3DGS 与 3DGS-SLAM：从点云地图到可渲染的三维场景

> 面向 FLMap.3 的下一步：在已有 LiDAR 几何基础上加入相机外观，做照片级三维重建。
> 本文分三层：**3DGS 本身是什么** → **3DGS-SLAM 在做什么** → **你这套设备该怎么落地**。
>
> **本文讲原理。要动手，看 [15-3dgs-pipeline.md](15-3dgs-pipeline.md)** ——
> 那里给了边缘 / 半边缘 / 全离线三条路线的算力判定与逐步工艺流程（含每步验收标准）。

---

## 1. 你现在的成果，缺的是什么

FLMap.3 已经能给你：

- 公制尺度准确的几何（Mid360 + FAST-LIO2，误差厘米级）
- 每帧的位姿 `/aft_mapped_to_init`
- 稠密点云 `/cloud_registered`、全量地图 `map.pcd`

缺的是**外观**。点云只有坐标和反射率，没有颜色、没有纹理、没有光照。
把相机架上去，自然想到"给点上色"——那就是彩色点云，但它只能"看"，不能"重新拍一张照片"。

而"三维场景重建"通常意味着下面三种能力之一，**它们的技术路线完全不同**：

| 你想要的能力 | 该做的技术 | 产物 |
|---|---|---|
| 导航、避障、测量、算体积 | TSDF / 体素 / mesh + 纹理（Voxblox、RTAB-Map、Open3D） | 水密网格 + 纹理贴图 |
| 任意视角"拍一张照片"、VR/数字孪生 | **3DGS / NeRF** | 数百万高斯 / 神经场 |
| 机器人边跑边重建、还要定位 | **3DGS-SLAM** | 位姿 + 可渲染地图 |

先确认你要的是第二行还是第三行 —— 这是两条投入差一个数量级的路。

## 2. 3DGS 是什么

**3D Gaussian Splatting**（Kerbl et al., SIGGRAPH 2023，Inria / TU Munich）。
一句话：**用几百万个半透明的椭球把场景"糊"出来，渲染时把它们投影到屏幕上并混合。**

### 2.1 和 NeRF 的核心区别

NeRF 把场景存进一个 MLP：查询"某条光线在某点上的密度和颜色"，要靠几百次网络前向 + 体渲染积分，
所以慢。3DGS 把场景存成**显式的、可微的几何图元**，渲染靠光栅化，因此快两个数量级。

| | NeRF | 3DGS |
|---|---|---|
| 场景表示 | 隐式（MLP 权重） | 显式（N 个高斯） |
| 渲染 | 体渲染积分，每像素几十次网络查询 | 光栅化 + alpha 混合，一次搞定 |
| 速度 | 秒级/帧 | **1080p 实时（几十到上百 fps）** |
| 训练 | 小时级 | **分钟级** |
| 显存/存储 | 小（几十 MB 权重） | 大（数百万高斯，几百 MB～GB） |
| 几何 | 靠 density 隐式表达，边界模糊 | 有明确中心点，但**不保证水密** |

### 2.2 一个高斯长什么样

每个高斯带 5 组参数：

```
μ  ∈ R³        中心位置
Σ  = R S Sᵀ Rᵀ 协方差（R 是旋转四元数，S 是三轴缩放）
α  ∈ [0,1]     不透明度
c  ∈ R^(16×3)  颜色，3 阶球谐系数（16 个系数 × RGB）
```

- **协方差拆成 R·S** 是关键设计：直接优化 Σ 会失去半正定性，拆成"旋转 × 缩放"后，
  梯度下降过程中永远是合法椭球。这也让高斯可以是**又长又薄的斜面** —— 墙面、桌面
  这类结构用几十个细长高斯就够，比球形点云高效得多。
- **球谐（SH）** 让颜色随视角变化，因此能看到高光、反射的方向性。这是它比"彩色点云"
  强的地方：不只是"这个点是什么颜色"，而是"从哪个方向看是什么颜色"。

### 2.3 渲染：三步

1. **投影**：用 EWA splatting 把 3D 协方差投影成 2D 椭圆：
   `Σ' = J W Σ Wᵀ Jᵀ`（W 是视图变换，J 是投影雅可比）
2. **排序**：把屏幕切成 16×16 的 tile，按 tile 并行；每个 tile 内按深度排序
3. **混合**：前到后 alpha 合成
   `C = Σ_i c_i α_i Π_{j<i}(1 − α_j)`

这三步全部可微，所以像素上的误差可以一直反传到 μ、Σ、α、SH。

### 2.4 训练：为什么它收敛得快

损失只有两项：

```
L = (1−λ)·L1 + λ·L_D-SSIM      λ = 0.2
```

真正让它"从稀疏点长成完整场景"的是**自适应密度控制**（每 100 次迭代一次）：

- 某个高斯在视空间的位置梯度很大（说明这块区域欠拟合）→ **clone**（复制一个）或 **split**（沿最大方差方向切成两个）
- 高斯太大 / 透明度太低 → **prune**（删掉）
- 每 3000 次迭代做一次 **opacity reset**：把所有 α 压到接近 0，让"没用但赖着不走"的
  漂浮高斯自然被剪掉，然后再长回来

**初始化几乎必须用 SfM 稀疏点**（COLMAP）。从随机点开始训练会卡在局部极小，
这是很多人"跑不出来"的第一个原因。而**你恰好有更好的初值：LiDAR 点云**（见 §4.2）。

### 2.5 代价与硬伤

| 问题 | 表现 | 原因 |
|---|---|---|
| 显存/存储大 | 一个房间 1–3 M 高斯，几百 MB | 每个高斯 ~59 个浮点数 |
| 漂浮物 | 空中出现絮状物 | 只在少数视角可见的高斯没被剪干净 |
| 几何不水密 | 拿去做碰撞检测会发现穿模 | 它优化的是"看起来对"，不是"几何对" |
| 依赖位姿精度 | 位姿有 1 cm 抖动就整体发虚 | 训练时位姿被当作真值 |
| 高光/反射 | 镜面处糊成一团 | SH 阶数有限，表示不了复杂反射 |

## 3. 3DGS-SLAM 是什么

**把 SLAM 的地图从"点/面元/体素"换成"高斯集合"，并让渲染误差反过来约束位姿。**

### 3.1 与经典 SLAM 的分工差异

经典 SLAM（ORB-SLAM、FAST-LIO）里，地图只服务于定位：特征点、路标、占据栅格。
3DGS-SLAM 里地图要**同时**服务定位和渲染，于是多了一个循环：

```
    ┌──────────── 渲染当前视角 ────────────┐
    │                                      ↓
  位姿 T  ──→  高斯地图 G  ──→  渲染图 Î  ──→  与真实图 I 比较
    ↑                                      │
    └──────── 反传梯度更新 T ←─────────────┘
                        （建图时反过来：固定 T，更新 G）
```

这就是它被称为"可微地图"的含义：**地图不是死的，位姿和场景在同一条梯度链上。**

### 3.2 跟踪与建图的两种耦合方式

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 紧耦合（end-to-end） | 每帧对位姿做可微优化（光度 + 深度损失） | 精度高、可利用全部像素 | 慢，且容易陷入局部极小 |
| 松耦合（前端 + 后端） | 前端用 ORB/VO/LIO 给位姿，后端只用 GS 建图与精化 | 快、鲁棒 | 前端漂移会原样传给地图 |

**经验**：纯视觉紧耦合在纹理丰富的小场景很惊艳，一出房间就崩；
工业上更常见的是"强前端 + GS 后端精化"。

### 3.3 代表工作（按模态分代）

| 代 | 代表 | 模态 | 关键点 |
|---|---|---|---|
| 第一代 | **SplaTAM**（CVPR'24）、**GS-SLAM**（CVPR'24） | RGB-D | 逐帧优化位姿 + 高斯增密；Replica/TUM 上效果好，需深度图 |
| 第一代 | **Gaussian Splatting SLAM / MonoGS**（CVPR'24 oral） | 单目 / RGB-D | 单目也能跑，但尺度不可观、漂移明显 |
| 第二代 | **Photo-SLAM**（CVPR'24） | 单目/RGB-D | ORB-SLAM3 前端 + GS 地图，能在 Jetson 上实时 |
| 第二代 | **CG-SLAM**（ECCV'24） | RGB-D | 强调几何一致性，深度更准 |
| 第三代 | **Gaussian-LIC / Gaussian-LIC2**、**GS-LIVO**、**LVI-GS**、**MM-Gaussian** | **LiDAR + IMU + 相机** | LIO 给几何与尺度，相机给外观 —— **与你的设备形态一致** |
| 专项 | **WildGS-SLAM**（CVPR'25） | RGB-D | 处理动态物体 |
| 专项 | **VINGS-Mono**（CVPR'25） | 单目 | 大场景分块 |

> 名字与年份以论文原文为准（这个方向 2024–2025 年论文极多，命名相近的不少）。
> 判断一篇工作是否适合你，只看三点：**用什么传感器、要不要深度、能不能在线跑**。

### 3.4 它们共同的硬伤

1. **没有回环检测**：走一圈回来，几何会错开一层。多数 GS-SLAM 只做局部一致性。
2. **单目尺度漂移**：你有 LiDAR，这条天然免疫。
3. **动态物体**：走过的人会被"固化"进地图，形成拖影高斯。
4. **显存随场景线性增长**：走 100 m 的长走廊，8 GB 卡基本撑不住，必须分块或做高斯生命周期管理。
5. **实时代价**：真正的实时（>10 fps）在桌面卡上是可行的，在 Orin 上很难。

## 4. 你这套设备该怎么落地

### 4.1 三条路线，先选一条

| 路线 | 做什么 | 工作量 | 建议 |
|---|---|---|---|
| **A. 纯点云上色** | 点云投到图像取色，得到 RGB 点云 | 1 天 | 只能"看"，不能渲染新视角。做基线可以 |
| **B. LIO 位姿 + 离线 3DGS**（推荐） | FAST-LIO2 出位姿，相机图像离线训练高斯 | 1–2 周 | **性价比最高**，直接产出照片级结果 |
| **C. 实时 3DGS-SLAM** | 自己实现或改开源，边跑边建 | 1–3 个月 | 论文级，先别碰 |

**推荐 B。** 理由很直接：你已经有一个**比 COLMAP 更准、更稠密、还带公制尺度**的位姿来源，
而 3DGS 最脆弱的两环（位姿估计、点云初始化）恰好都被 FAST-LIO2 解决了。
反过来，如果你的目标是发论文，C 的增量才在"用 LiDAR 解决纯视觉 GS-SLAM 的尺度与无纹理问题"。

### 4.2 为什么 LiDAR 初始化的高斯更强

3DGS 的两个经典痛点，LiDAR 直接消掉：

| 纯视觉 3DGS 的痛点 | 用 LiDAR 后的情况 |
|---|---|
| 需要 COLMAP 跑 SfM，弱纹理场景直接失败 | 不需要 SfM，位姿和点云都是现成的 |
| 单目尺度不可观（场景大小是个任意数） | 公制尺度，直接对得上真实世界 |
| 白墙、地板、玻璃上没特征，长出漂浮物 | 每个 LiDAR 点都是一个高斯的出生点，几何有锚 |
| 室外、大场景天空区域发散 | 远距离点云提供背景骨架 |

具体做法：把 `/cloud_registered` 的点变换到各关键帧相机系，投影到图像上取颜色，
作为初始高斯的中心与颜色（SH 的 0 阶项）；然后把相机图像作为监督信号继续训练。

### 4.3 完整管线

```
① 采集（狗端，一次跑完）
   rosbag record: /livox/lidar /livox/imu /camera/image_raw /camera/camera_info
   同时 FAST-LIO2 已在算位姿

② 标定
   相机内参 K、畸变 D      ← 棋盘格，10 分钟
   LiDAR→相机外参 T_lc     ← 棋盘格平面约束 / 开源工具
   （这步精度决定成品有没有"重影"，是整条链最容易被低估的环节）

③ 位姿
   /aft_mapped_to_init 给 T_world_lidar
   T_world_cam = T_world_lidar · T_lidar_cam

④ 初始化
   LiDAR 点云 → 变换到相机系 → 投影取色 → 生成初始高斯

⑤ 训练
   固定位姿训练（先做）→ 再开位姿/曝光联合优化（后做）
   损失 = L1 + D-SSIM (+ 深度正则，把 LiDAR 深度作为先验)

⑥ 评估与导出
   PSNR / SSIM / LPIPS（渲染质量）
   点到点云距离（几何保真）
   导出 .ply / .splat，用 SuperSplat、CloudCompare、LichtFeld 查看
```

### 4.4 坐标系与标定公式

```
T_world_lidar  ← FAST-LIO2 输出（/aft_mapped_to_init，frame_id 通常是 camera_init 或 map）
T_lidar_cam    ← 你标定的外参
T_world_cam    = T_world_lidar · T_lidar_cam          ← 训练时每帧的相机位姿
p_cam          = T_lidar_cam⁻¹ · p_lidar              ← 点云投到相机系
u, v           = K · p_cam / z                        ← 投到像素
```

一个高频错误：**`/aft_mapped_to_init` 的旋转与 Mid360 的坐标系不是同一个手性/朝向**，
直接当相机外参用会出现"整体歪 90°"。务必先用一帧点云投到图像上肉眼对齐（能在墙上看到
点云与像素吻合），再开始训练。

### 4.5 你的硬件能跑到什么程度

**RTX 5060 Ti / 8 GB**（已确认，驱动 595.99）。这个显存是硬约束，具体表现：

| 场景 | 1080p / SH 3 阶 | 建议 |
|---|---|---|
| 单房间（20–60 m²） | 1–3 M 高斯，2–4 GB，**可以** | 主力场景 |
| 一层楼 / 多个房间 | 5 M+ 高斯，**会爆** | 分块（chunk）后分别训练，或降 SH 到 1–2 阶 |
| 分辨率 2K / 4K | 显存 ×1.5–2 | 降到 1280×720 训练，再上采样 |
| 实时 GS-SLAM（SplaTAM 类） | 勉强，需降分辨率 | 不建议在 8 GB 上做实时 |

省显存的三个开关（按收益排序）：**SH 降到 0–1 阶**（省 3/4 颜色参数）、
**图像降采样到 960×540**、**限制单块高斯数量并做分块**。

### 4.6 相机怎么选

| 方案 | 优点 | 缺点 | 适合 |
|---|---|---|---|
| Go2 前置相机（现有） | 零成本 | 卷帘快门、自动曝光、画质一般 | **先验证管线** |
| RealSense D435i / D455 | 有 SDK、有 IMU、生态好 | RGB 是卷帘快门，深度与 LiDAR 重复 | 快速起步 |
| 全局快门工业相机（USB3/GigE） | 无果冻效应、可硬件触发 | 要自己处理驱动与同步 | 认真做重建 |
| 双目/鱼眼（OAK-D 等） | 自带同步与深度 | 视场大但畸变重 | 大场景 |

**关键指标不是分辨率，是：全局快门 + 手动曝光锁定 + 时间戳可对齐。**
自动曝光会让同一面墙在相邻帧亮度跳变，3DGS 会学出一堆"花斑"。

## 5. 分阶段路线图

| 里程碑 | 内容 | 验收标准 | 预计 |
|---|---|---|---|
| **M0 环境** | CUDA + PyTorch + gsplat/Nerfstudio；一条命令能训练官方 demo | 官方 `bicycle` 数据集 30 分钟内出结果 | 半天 |
| **M1 打通数据** | 用 Go2 前摄录 1 分钟，标定内参，LiDAR 点投到图像肉眼对齐 | 投影图里头线、墙角与像素重合 | 1–2 天 |
| **M2 小场景离线** | 单房间，固定 LIO 位姿，LiDAR 点初始化，训练 30k iter | PSNR > 25，渲染新视角无明显漂浮物 | 1 周 |
| **M3 大场景** | 分块 + 位姿精化 + 深度正则，多房间拼起来 | 走完整层不爆显存，接缝不重影 | 2–3 周 |
| **M4 在线化（可选）** | 增量建图、关键帧策略、高斯剪枝 | 边跑边看，延迟 < 1 s | 1–3 月 |

**别跳 M1。** 90% 的失败案例都发生在这一步没做扎实：位姿对不上、外参差 2 cm，
后面怎么调参都是糊的。

## 6. 十个必踩的坑

1. **外参差 1–2 cm** → 所有东西双重影。用点云投影到图像逐像素对齐，不要只信标定报告。
2. **自动曝光没关** → 相邻帧整体亮度跳变，高斯学出噪点。
3. **卷帘快门 + 快速转向** → 图像内部错位，高斯被拉成斜条。
4. **时间戳不同源** → 相机与 LiDAR 差 20 ms，走 1 m/s 就偏 2 cm。
5. **LiDAR 点太稀**（16 线在远处只有零星点）→ 远处墙长不出来，需要"距离自适应增密"。
6. **玻璃与镜面** → 高斯会穿过去，在镜子后面生成一个"假房间"。要么遮挡，要么后处理删。
7. **动态物体**（人、门、宠物）→ 拖影。录制时清场，或做动态掩膜。
8. **SH 阶数开满 + 大场景** → 8 GB 直接 OOM。先 0 阶跑通再往上加。
9. **训练完不做几何检查** → 渲染很漂亮但尺度错 10%。一定用 LiDAR 点云做几何校验。
10. **没有分块就直接跑整层楼** → 高斯数量线性增长，最后既跑不动也看不清。

- 官方实现：`graphdeco-inria/gaussian-splatting`

- 评测：`INRIA 的 metrics.py`（PSNR/SSIM/LPIPS）

**3DGS-SLAM 代码**

- `nerf-slam` 系：SplaTAM、MonoGS（Gaussian Splatting SLAM）、GS-SLAM
- Photo-SLAM（ORB-SLAM3 + GS，工程完整度高）
- LiDAR 融合方向多为 2025 年新工作，代码质量参差，先读论文再决定是否复用

**必读三篇**

1. Kerbl et al., *3D Gaussian Splatting for Real-Time Radiance Field Rendering*, SIGGRAPH 2023
2. Matsuki et al., *Gaussian Splatting SLAM*, CVPR 2024（理解"可微地图 + 位姿"最清楚）
3. 任一 LiDAR-Inertial-Camera 融合工作（Gaussian-LIC 系列），对照自己的传感器配置

## 8. 结论

- **3DGS 是渲染技术**：把场景变成可微的椭球集合，换来实时、照片级的新视角合成，
  代价是显存和"几何不保证准确"。
- **3DGS-SLAM 是 SLAM 技术**：让渲染误差参与定位，地图既是几何也是外观；
