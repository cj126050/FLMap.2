# 16. 方案二（半边缘）详解与无硬件验证

> 上一篇（[15-3dgs-pipeline.md](15-3dgs-pipeline.md)）判定了三条路线的取舍，选了 B。
> 这一篇把 B 拆到可执行粒度，并给出**在没有相机、没有狗的情况下把 B 验证到底**的方法。
>
> 本文所有数字都是在本机实测得到的，不是估算。标注「实测」的行可以直接复现。

## 0. 为什么"没有硬件"不等于"只能等"

方案 B 的七个环节里，**只有两个真的依赖硬件**：

| 环节 | 依赖硬件？ | 没有相机时怎么验 |
|---|---|---|
| B0 标定 | 需要相机+雷达同时看棋盘格 | 用带 GT 标定的公开数据集反向验证算法 |
| B1 采集 | 需要相机 | **跳过**，用数据集代替（这一步本来就没法脱离硬件） |
| B2 关键帧筛选 | 不需要 | ✅ 合成数据即可完整验证 |
| B3 传输 | 不需要 | ✅ 本地目录模拟 |
| B4 预处理（位姿链） | 不需要 | ✅ 这是最容易错、也最该先验的一步 |
| B5 训练 | 需要 GPU（已有） | ✅ 公开数据 + 现有 8 GB 卡 |
| B6 验收 | 不需要 | ✅ 有 GT 的数据反而能算绝对误差 |
| B7 后处理 | 不需要 | ✅ 拿到 `.ply` 之后的事 |

也就是说：**B2 / B3 / B4 / B6 可以百分之百验证，B5 可以验证到超参与显存预算，只有 B0 / B1 必须等硬件。**
而 B4 恰好是全流程最容易出错的地方（坐标约定、位姿链），把它先验掉，是最划算的。

## 1. 系统分解：六个可独立测试的单元

不要把它当成一条"跑起来才知道对不对"的长链。切成六块，每块有独立输入输出和验收：

```
① 采集     传感器 -> 帧(图+点云+位姿)       ← 需硬件（B1）
② 筛选     帧序列 -> 关键帧集合              ← kf_core.py（纯函数）
③ 装配     关键帧 -> nerfstudio 数据集        ← build_dataset.py
④ 训练     数据集 -> 高斯模型 .ply           ← nerfstudio / gsplat
⑤ 验收     .ply + GT -> 数字                 ← check_projection.py + ns-eval
⑥ 后处理   .ply -> mesh / 纹理               ← SuGaR / 2DGS
```

关键设计：**②必须是无 ROS 依赖的纯函数**。狗端节点 import 它，模拟器也 import 它。
如果模拟端另写一套筛选逻辑，"模拟通过"就推不出"现场通过"——这是模拟验证最容易犯的错。

本仓库的实现：

| 文件 | 职责 | 依赖 |
|---|---|---|
| `tools/sim/kf_core.py` | 关键帧筛选、位姿 delta、坐标转换、覆盖率统计 | 只有 numpy |
| `tools/sim/test_kf_core.py` | 上述模块的回归测试（6 项） | — |
| `tools/sim/make_synthetic.py` | 生成 GT 位姿 + GT 深度的合成房间 | numpy/PIL |
| `tools/sim/sim_edge_loop.py` | 数据集 → `kf/`（模拟狗端 B2） | kf_core |
| `tools/sim/build_dataset.py` | `kf/` → `transforms.json` + `init.ply` | kf_core |
| `tools/sim/check_projection.py` | 投影自检（M1 / B6 验收） | kf_core |
| `tools/sim/run_sim.sh` | 一键串联 L0 全流程 | — |

## 2. 数据契约（先定死，再写代码）

改格式比改代码贵得多。三份文件定死之后，模拟端、狗端、训练端才能互换。

### 2.1 关键帧目录 `kf/`

```
kf/
├── 000001/
│   ├── image.jpg        # 1280×720 q90，约 150 KB
│   ├── pose.txt         # 第 1 行 "# timestamp <t> frame_index <i> reason <why>"
│   │                    # 后 4 行 = 4×4 c2w（OpenCV 约定，行优先）
│   └── cloud.pcd        # binary，x y z intensity（float32），约 240 KB/15k 点
├── 000002/
└── index.json
```

`index.json`（程序读这个，不要读目录列表）：

```json
{
  "scene": "room0",
  "source": "synthetic | replica | bag",
  "pose_convention": "opencv_c2w",
  "camera": {"model":"PINHOLE","width":1280,"height":720,
             "fx":1130.0,"fy":1130.0,"cx":639.5,"cy":359.5,"dist":[0,0,0,0]},
  "kf_config": {"min_trans_m":0.15,"min_rot_deg":5.0,"max_gap_s":3.0,"max_points":15000},
  "stats": {"frames_total":120,"frames_kept":60,"keep_ratio":0.5,
            "path_m":12.48,"yaw_coverage_deg":356.0,"mean_points":14986},
  "frames": [{"id":1,"src_index":0,"t":0.0,"reason":"first","points":14998}]
}
```

**`reason` 字段不是装饰**。现场出问题时，"为什么这一帧被选中"直接决定你怀疑哪个阈值。

### 2.2 位姿链（最容易错的地方）

```
T_world_body   ← /aft_mapped_to_init（FAST-LIO2 输出，odom→body=IMU）
T_body_lidar   ← FAST-LIO2 配置里的 extrinsic（取逆）
T_lidar_cam    ← B0 标定的结果
─────────────────────────────────────────────────
T_world_cam = T_world_body · T_body_lidar · T_lidar_cam
T_nerfstudio = T_world_cam · diag(1,-1,-1,1)     ← OpenCV → OpenGL
```

三个已经踩过的坑：

1. **漏掉 `T_body_lidar`**。`/aft_mapped_to_init` 给的是 IMU/body 位姿，不是雷达位姿。
   Mid360 的 IMU 与激光器有安装偏移，漏掉会让整幅图绕着一个偏心的点旋转。
2. **`diag(1,-1,-1,1)` 加两次或一次都没加**。加两次等于没加，表现为图像上下颠倒。
3. **把 `yaw` 当成绕光轴转**。相机系 z 是光轴，绕它转是 roll。判断朝向必须用世界系
   x-y 平面的 `atan2(fwd_y, fwd_x)`。

### 2.3 `transforms.json`

`build_dataset.py` 直接产出 nerfstudio 格式（`camera_model: OPENCV`），并写入
`"ply_file_path": "init.ply"`。**不需要跑 COLMAP**。

一处必须提前知道的现实：`splatfacto` 在 `random_init=False` 时读的是 COLMAP 的
`sparse/0/points3D.bin`，**不直接吃 `.ply`**。两条路：
① 写十几行把 `init.ply` 转成 `points3D.bin`（半天，一次性）；② 自己写 gsplat trainer（1–2 天）。
先走 ①。

## 3. B0–B7 的执行细节

### B0 标定（0.5–1 天，唯一不能压缩的一步）

| 步 | 动作 | 产出 | 验收 |
|---|---|---|---|
| B0.1 | 棋盘格 30 张，覆盖画面四角 + 倾斜 | `intrinsics.yaml` | 重投影误差 < 0.3 px |
| B0.2 | 相机侧 `solvePnP` 得 `T_cam_board` | — | 内点率 > 80% |
| B0.3 | 雷达侧 RANSAC 拟合棋盘平面 + 强度阈值取角点，得 `T_lidar_board` | — | 平面拟合残差 < 5 mm |
| B0.4 | 复合求 `T_lidar_cam`，多姿态取平均并算标准差 | `T_lidar_cam.yaml` | 各姿态解算差异 < 5 mm |
| B0.5 | **投影叠图**：点云投到图像 | `overlay.png` | 墙角/门框重合 < 2 px |

B0.5 是唯一可信的验收。数字漂亮但叠图不重合的标定，一定是错的。

### B1 采集（需硬件）

| 项 | 值 | 理由 |
|---|---|---|
| 曝光 | `auto_exposure=1`，手动 `exposure_time_absolute=120` | 自动曝光让同面墙亮度跳变，3DGS 学出花斑 |
| 白平衡 | 固定 | 同上 |
| 增益 | 固定 | 同上 |
| 时间戳 | ROS 时钟（已与 PC 授时同步） | 与 `/livox/lidar` 差 < 10 ms |
| 分辨率 | 1280×720 | 8 GB 显存下的甜点，2K 上去会先爆显存 |

### B2 关键帧筛选（已实现并测试）

三个触发条件，任一满足即存：

```
① 平移 ≥ 0.15 m      ② 转角 ≥ 5°      ③ 距上一帧 ≥ 3 s
```

0.15 m 的来源：720p / 水平 FOV 90° 时，0.15 m 对应相邻帧约 75% 重叠。

**实现里有两个细节决定了它能不能用**：

- 阈值比较必须带容差（`EPS = 1e-6`）。位姿是 6 位小数的里程计，
  `0.05*3` 与 `0.05*6` 之差算出来是 `0.14999999999999997`，严格 `>=` 会让
  "刚好等于阈值"的帧随机丢失，表现为关键帧间距时紧时松。
- 不能只靠平移触发。相机原地环视（转角大、位移 0）时，只靠平移会一帧不存。

### B3 传输

`rsync -a unitree@192.168.123.18:~/bags/<ts>/kf/ ./data/<ts>/`，千兆实测 91 MB/s。
200 帧约 80 MB，**1 秒级**。不必做实时推流——那会把"采集成败"和"网络成败"耦合成一个故障点。

### B4 装配

`build_dataset.py`：平铺图像、转坐标、合并点云降采样到 200k、写 `meta.json`。

`meta.json` 必须记录 `T_lidar_cam` 的**数值或校验和**以及 `t_offset`。
同一场景用不同外参训练出的模型不可比——这是复现实验的最低要求。

### B5 训练

```bash
/usr/bin/python3.10 -m venv ~/venvs/gs && source ~/venvs/gs/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cu128
pip install nerfstudio
ns-train splatfacto --data data/<ts> --pipeline.model.random-init False \
    --max-num-iterations 30000 --vis viewer+tensorboard
```

8 GB 显存三档（按收益排序）：`sh-degree 1` → `downscale-factor 2`（960×540）→ 分块限高斯数。

### B6 验收（四个指标，缺一个都不算过）

| 指标 | 阈值 | 抓什么 |
|---|---|---|
| PSNR（留出 1/8 帧） | > 24 可用，> 28 好 | 外观拟合 |
| SSIM | > 0.80 | 结构 |
| 几何中位误差 | < 5 cm | 高斯中心到最近 LiDAR 点 |
| **投影叠图目检** | 墙角重合 | 横向错位（数字抓不到，见 §6.3） |

### B7 后处理

`.ply` 直接交付（几 MB，SuperSplat 可播）；要 mesh 用 2DGS / SuGaR 正则化后 Poisson 提取。

## 4. 无硬件验证：三级阶梯

不要一步跳到"下载 20 GB 数据集"。每级只回答一个问题，不通过就停下修。

| 级 | 数据 | 用时 | 回答什么问题 | 不通过的处置 |
|---|---|---|---|---|
| **L0** | 本仓库合成（自带 GT） | 10 分钟 | 代码路径、目录契约、坐标约定对不对 | 修代码，别往下走 |
| **L1** | Replica（合成但真实渲染） | 半天 | 训练能不能到 PSNR 28、显存够不够 | 调超参 / 换分块策略 |
| **L2** | 真实 LiDAR+相机数据集 | 1 天 | 真实噪声、真实标定误差下还剩多少 | 加鲁棒性，或改采购要求 |

### 4.1 L0：本仓库合成数据（已跑通）

```bash
cd ~/FLMap.3
./tools/sim/run_sim.sh data/sim 120
```

它做四件事：生成房间 → 筛关键帧 → 装配数据集 → 投影自检 + 单元测试。

**实测输出**（120 帧，640×360）：

```
[KF] 120 帧 -> 60 个关键帧 (50.0%), 平均 14986 点
[KF] 轨迹长 12.48 m / 11.9 s, 朝向覆盖 356 deg
[DS] 60 帧, init.ply: 899184 -> 200000 点
[PROJ] 同帧深度误差: 0–6 mm，图内落点 99.2–99.3%
[PROJ] 跨帧 1->2: 重叠 86.6%, 深度 inlier 100.0%, 中位 1.9 mm, 颜色差 8.0
```

50% 保留率是可验证的正确值：1.05 m/s × 10 fps = 0.105 m/帧，0.15 m 阈值 → 每 2 帧一选。

`data/sim/proj_check.png` 是投影叠图，洋红点应铺满墙和地面且贴合几何边缘。

### 4.2 L1：Replica

```bash
# 官方仓库（按 README 下载 room0，约 1.5 GB）
git clone https://github.com/facebookresearch/Replica-Dataset
# 目录要求：results/frame000000/{rgb.png,depth.png} + traj.txt + meta.json

/usr/bin/python3 tools/sim/sim_edge_loop.py --scene <replica>/room0 --out data/rep/kf
/usr/bin/python3 tools/sim/build_dataset.py --kf data/rep/kf --out data/rep/ds
ns-train splatfacto --data data/rep/ds --max-num-iterations 30000
```

⚠️ **Replica 官方 `traj.txt` 是 OpenGL 约定**，本仓库内部契约是 OpenCV。
要先转一次（`T_cv = T_gl @ diag(1,-1,-1,1)`，该矩阵自逆）。漏了这一步，训练必然糊。

⚠️ Replica 没有 `meta.json`，需要手写一个（内参为 `fx=fy=600, cx=599.5, cy=339.5`，
1280×720）。**这个内参是官方值，不要用自己猜的**。

### 4.3 L2：真实数据集

| 数据集 | 传感器 | 为什么选 / 不选 |
|---|---|---|
| **Newer College**（Oxford） | Ouster OS-1 + 相机 + GT | ✅ 有 GT、有标定、室内外混合 |
| **FusionPortable**（HKUST） | LiDAR + 相机 + IMU，手持 | ✅ 手持室内，最接近 Go2 的作业形态 |
| Hilti SLAM Challenge | LiDAR + 相机，工地 | ✅ 退化场景（长走廊、玻璃） |
| KITTI / nuScenes | 车载 | ❌ 室外高速、大量动态车，与室内巡检不同 |
| TUM RGB-D | 只有 RGB-D | ⚠️ 可验训练，但验不了 LiDAR 分支 |

**必须知道的一个局限**：这些数据集的 LiDAR 都是旋转式（Ouster/Velodyne），
与 Mid360 的**非重复扫描**模式不同——点云在空间的分布不一样（Mid360 单帧稀疏、
多帧累积才密）。所以 L2 能验证"真实噪声 + 真实标定误差"的影响，
**不能验证 Mid360 特有的退化**（如近距离白墙、玻璃）。

## 5. 模拟能验证什么、不能验证什么

这张表比任何流程都重要，因为它决定你什么时候可以掏钱。

| ✅ 能验证 | ❌ 不能验证 |
|---|---|
| 目录契约、字段完整性 | 你自己相机的内参（畸变系数完全不同） |
| 坐标链（body/lidar/cam/OpenGL） | 你自己的 LiDAR-相机外参 |
| 关键帧阈值是否合理 | 时间同步误差（数据集已对齐到微秒） |
| 训练超参与显存预算 | 曝光锁定效果（数据集曝光已固定） |
| 验收指标是否算得出来 | 狗端算力（模拟全在 PC 上跑） |
| 分块策略、mesh 提取 | Mid360 在弱纹理/玻璃前的退化 |
| 失败模式是否覆盖 | 相机与雷达的**机械刚性**（振动会让外参漂） |

第六行最容易自欺：在 L1 上 PSNR 30 dB 就以为万事大吉，而真实场景里
1 cm 的外参误差会让它掉到 20 dB。所以 §6 的扰动实验是必须做的。

## 6. 验收工具的可信度：先证明它能报错

一个检查工具如果在错误输入下也通过，它就没有价值。所以对 `check_projection.py`
做了三组注入实验（把第 2 帧位姿故意改错，其余不变）：

| 注入方式 | 深度 inlier | 中位误差 | 颜色差 | 判据是否报警 |
|---|---|---|---|---|
| 无（基准） | 100.0% | 1.9 mm | 8.0 | — |
| 沿光轴 5 cm | **74.1%** | **40.5 mm** | 8.3 | ✅ 深度判据报警 |
| 横向 5 cm | 100.0% | 1.9 mm | 9.0 | ⚠️ 两条都勉强 |
| 横向 20 cm | 99.2% | 1.9 mm | **13.5** | ✅ 颜色判据报警 |

**结论（这就是检测下限）**：

- **深度判据**只对**沿视线方向**的误差敏感（≥ 3 cm 可靠）。横向平移不改变深度。
- **颜色判据**只对**超过一个纹理单元**的横向错位敏感（本数据纹理 0.45 m，20 cm 才明显）。
- **5 cm 级横向错位，两条自动判据都不可靠 → 必须靠投影叠图人工目检。**

这个结论直接写进现场 SOP：`stop` 之后不要只看数字，一定要打开叠图看一眼墙角。

## 7. 买相机的门槛（量化，逐条判）

只有全部通过才采购。任何一条不过，先改方案而不是买更贵的相机。

| 编号 | 门槛 | 怎么测 | 不过怎么办 |
|---|---|---|---|
| **G1** | L0 全流程 < 10 min 且自检通过 | `./tools/sim/run_sim.sh` | 修代码 |
| **G2** | L1 Replica 单房间 **PSNR ≥ 28 dB** | `ns-eval` | 管线有问题，别买 |
| **G3** | L2 真实数据 **PSNR ≥ 24 dB** | 同上 | 加鲁棒性（曝光归一、深度损失） |
| **G4** | 外参扰动 ±1 cm → PSNR **掉 ≤ 3 dB** | 见下 | 掉 10 dB = 必须买**硬触发**相机 |
| **G5** | 单房间端到端 < 40 min | 计时 | 分块或降分辨率 |

### G4 是这套方案里最有价值的一个实验

它用**扰动**反推"标定精度要求"，从而**反推该买什么档次的相机**：

```bash
# 在 L2 数据集上，把 T_lidar_cam 人为偏 1 cm，重训，看 PSNR 掉多少
for d in 0 0.005 0.01 0.02; do
  apply_extrinsic_offset $d && ns-train splatfacto --data data/l2 --max-num-iterations 15000
done
```

- 掉 ≤ 3 dB → 软同步 + 事后标定够用，买普通 USB3 工业相机即可
- 掉 5–10 dB → 需要**硬件触发**（相机与雷达共时钟）+ 出厂标定
- 掉 > 10 dB → 单相机方案本身不稳，考虑双目/多相机或换回纯点云

这个实验在**没有相机的时候就能做**，结论直接决定预算。这就是"先模拟后采购"的最大收益。

## 8. 采购清单（按 G4 的结论选档）

| 项 | 要求 | 参考型号 | 备注 |
|---|---|---|---|
| 相机 | **全局快门**、USB3、≥720p | 海康 MV-CS016-10UC / 大恒 MER2-503-36U3C | 卷帘快门配快速转向会把高斯拉成斜条 |
| 镜头 | 低畸变 6–8 mm，HFOV 75–90° | 对应 C 口定焦 | 畸变大了标定收敛差 |
| 同步 | 支持外触发（strobe/trigger） | — | Mid360 有 PPS，可分频给相机 |
| 支架 | 相机与雷达**刚性同体** | 铝件 / 3D 打印加筋 | 振动导致外参漂移，比标定不准更常见 |
| 存储 | 已有 NVMe 469 GB | — | 够存 100+ 次 |

### 一个必须提前想清楚的物理约束

**Mid360 是 360°×59°，单相机只有约 90°×60°。**

也就是说单相机只能覆盖 **1/4 的水平范围**。这意味着：

- 3DGS 只能重建相机看到的部分（雷达有几何但没有外观）
- 采集时必须**绕行 + 每面墙都正对一次**，不能像纯建图那样随便走
- 或者上多相机（成本 ×3）、或加云台（复杂、引入时间同步问题）

这个约束会直接改变采集 SOP。**如果没想清楚就买一个相机，会发现只能重建四分之一个房间。**

---

## 9. 执行顺序（建议）

```
第 1 天    L0 跑通（本仓库已就绪，一条命令）           → 过 G1
第 2–3 天  L1 Replica + 训练 + ns-eval                → 过 G2
第 4–5 天  L2 真实数据集（Newer College 或 FusionPortable）→ 过 G3
第 6 天    G4 扰动实验                                  → 决定相机档位
第 7 天    按 G4 结论下采购单
────────────────────────────────────────────────────────
到货后     B0 标定（1–2 天）→ B1 采集 → B5 训练 → 对比 L2 的数字
```

**第 6 天之前不要下单。** G1–G3 任何一条不过，说明问题在管线而不是硬件，
买相机只会把问题往后推一周。

## 10. 已知风险

| 风险 | 表现 | 缓解 |
|---|---|---|
| 模拟数据的纹理太"友好" | L0/L1 轻松 30 dB，现场掉到 20 dB | 故意在合成数据里加弱纹理区（白墙）再跑一次 |
| Replica 是合成渲染 | 没有真实传感器噪声 | 必须做 L2，不能停在 L1 |
| 位姿来自 LIO，无回环 | 走一圈回来错层 | 分段训练 + 人工拼接；或引入回环后端 |
| 单相机 FOV 不足 | 只重建 1/4 场景 | 绕行 SOP 或上多相机 |
| 8 GB 显存 | 大场景 OOM | SH 降到 1、540p、分块 |
| 数据集 License | 商用受限 | 采购决策前确认数据只用于验证 |
